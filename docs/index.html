MERIDIAN Pascal

A Turbo Pascal-style compiler, libraries, emulator and IDE for the MERIDIAN 816 home computer and its SCHUB RISC-V co-processor.

Getting started

You need Node.js 18 or newer. Nothing else has to be installed.

node ide/server.js

Then open http://127.0.0.1:8165/. On the first start the examples are copied into the project folder projects/. Open hello.pas and press F5: the program is compiled to hello.mer and runs in the built-in MERIDIAN emulator.

program Hello;
uses Crt;
var i: integer;
begin
  ClrScr;
  TextColor(Yellow);
  WriteLn('HELLO FROM PASCAL!');
  for i := 1 to 5 do WriteLn(i, ' * ', i, ' = ', i * i);
end.

To run it on the real machine, copy the .MER file to /media/fat/games/MERIDIAN/ and use Load program in the MiSTer menu, or press F8 in the IDE to send it over the network with the MERIDIAN repository's tools/senden.py. The program starts at once; when it ends, the MERIDIAN is back at READY.

On the MERIDIAN itself: the PASCAL cartridge

PASCAL.MOD is a cartridge with an editor and a compiler that run on the MERIDIAN 816 itself, like Turbo Pascal on an old home computer. Build it with

node compiler/mkcart.js            # -> PASCAL.MOD (also: npm run cart)
node compiler/mkcart.js -o X.MOD   # another file name
node compiler/mkcart.js -l         # also a listing, PASCAL.lst

or with the PASCAL cartridge button above the emulator screen in the IDE (it starts the cartridge in the emulator and saves PASCAL.MOD in the project). On the MiSTer, copy it to /media/fat/games/MERIDIAN/ and choose it under Insert cartridge: the MERIDIAN then starts into the editor (OSD Cartridge start: Off or F10 goes to BASIC). It needs the SDRAM module.

The editor looks like the workshop and its text editor EDIT (F8 in BASIC): the top line holds the tab PASCAL and the F-keys, the second line the file, drive, target and size with the cursor's line and column on the right, then 26 lines of text; the line below the text shows the Ctrl keys (while a program is stopped, the debugger's keys), and the last line shows a message, or more keys when there is none. Where EDIT has a key for something, the editor has the same one.

Crash protection. A program that hangs or crashes can only be stopped by a reset. The text stays in the expansion RAM, which a reset leaves alone, and the editor keeps a note of its length, name and cursor next to it. When the cartridge starts again after a reset and the text was not saved, the editor asks: Unsaved text from before the restart: NAME, n bytes. Recover it? (Y/N). Y brings it back as it was, unsaved (F2 saves it). If the program wrote into the text, the question says damaged and the editor tells how many bytes look wrong (characters that text never holds); check the text before saving it. Leaving the editor with F10, or a saved text, leaves nothing to recover.

The cartridge holds all library units (System, Crt, Graph, Sprites, Audio, Input, Dos, Blitter, Copper, Schub, Basic), compiled by the cross compiler in its far code model, plus a table of their routines. The on-device compiler (cart/ncomp.pas, written in Pascal) is a one-pass compiler that writes 65C816 code straight into bank $30 and calls the library in ROM. While a program runs, bank 0 is saved in bank $31 and the editor's state comes back afterwards; a runtime error or Halt also returns to the editor.

Runtime errors. After F5, a runtime error is shown with the line it happened in, for example Runtime error 201 at line 17 (or ... in MYUNIT.PAS), and the cursor goes to that line; a click on the message goes there again. A program stopped another way (Esc) shows where it stopped. For this, the code F5 runs stores the line of every statement, which makes it about 10 to 15 percent slower; {$D-} in the text turns that off from there on ({$D+} on again). Programs saved with F7 never have it. Lines are counted up to 4095.

The debugger. Ctrl+B sets or clears a breakpoint on the cursor's line (the line turns red). F5 then runs the program until it reaches one; Ctrl+F7 runs it and stops at the first statement. A stopped program's line is green, and the editor waits:

F5go on, to the next breakpoint or the end
F7the next line, also into a procedure or function
F8the next line in this procedure (calls run through)
F4run to the cursor's line
Ctrl+F2end the program
Ctrl+Wwatch a global variable: total, p.x, a[3], s[1] (an empty name takes the last watch away; up to 6). The watches are shown at the bottom while the program is stopped.

The program's text screen comes back when it goes on (a graphics picture does not). Changing the text ends a stopped program. It works in both editors for 65C816 and SCHUB programs; breakpoints are lines of the program (not of its units), up to line 4095. A program run with breakpoints calls the debugger at every line and is slower; without breakpoints F5 runs it as before.

The editor on SCHUB. On a core with SCHUB the cartridge starts a SCHUB build of the same editor, compiler and assembler (compiler/mkschubide.js; the welcome line says on SCHUB). It compiles about ten times faster (SNAKE.PAS: 0.3 instead of 3.5 seconds on a MiSTer) and scrolls about three times faster; what it produces is byte for byte the same, for both targets. It lives in banks $A0–$AF, so programs keep their usual places. To run a program (F5, Ctrl+R) it stops SCHUB, keeps bank 0 in bank $B0 while the program runs on the 65C816 or on SCHUB, and then carries on where it was. Ctrl+F10 leaves it for the 65C816 editor; F10 goes to BASIC as usual. On a core without SCHUB the cartridge starts the 65C816 editor.

Language on the MERIDIAN: programs with uses of the built-in units, const (typed constants too: arrays and records, (x: 1; y: 2)), initialised global variables (var k: integer = 5;), type, var, nested procedures and functions with value, var and const parameters (string, array, record and set parameters too), integer word byte shortint longint real char boolean string string[n], arrays (up to 8 dimensions), records with variant parts, sets (set of, constructors with expressions, + - * in = <> <= >=, Include/Exclude), pointers with New/Dispose, enumerations, subranges, if while repeat for case with, Exit Exit(value) Break Continue Halt, += and -=, Write(Ln) with widths (r:w:d for reals), Read(Ln), Inc Dec Str Val Ord Chr Succ Pred Odd Abs Sqr Sqrt Trunc Round Int Frac Length SizeOf Low High Lo Hi Swap Assigned Addr Concat GetMem FreeMem, string(...) casts, Mem[] MemW[] MemL[] and @, and the directives {$DEFINE} {$UNDEF} {$IFDEF} {$IFNDEF} {$ELSE} {$ENDIF} (predefined as on the PC: MERIDIAN, M816 CPU65C816 or SCHUB CPURV32) and {$I file} (an include file from the current drive; .PAS is added when the name has no ending). As in Turbo Pascal, every directive can also be written with (*$ ... *), such as (*$R+*) or (*$I file*). and/or stop as soon as the result is known. The library's Sin Cos ArcTan Exp Ln Power work as on the PC. Files (Text, file of T, file), {$R+}, {$Q+} and {$I-} work as on the PC, too (see Files and Range and overflow checks). So do goto/label, open array parameters, procedural types and objects (see Language), with these limits: up to 16 object types with virtual methods and 16 virtual methods each; inherited and TAncestor.Method inside methods; a routine nested in a method reaches the object's fields and methods as Self.x.

Your own units: uses MyUnit reads MYUNIT.PAS from the current drive and compiles it together with the program (file names are the first 8 letters of the unit name). A unit has unit, interface and implementation parts, may use other units (also in its implementation part) and may end with begin or initialization code, which runs before the program. Only what the interface declares is visible to the program. An error inside a unit shows as Error in MYUNIT.PAS line n, and the editor asks whether to open the unit there. Y saves the program first (asking for a name if it has none), opens the unit and puts the cursor on the error; F9, F5 or F7 in the unit then save it, open the program again and compile it.

Functions can return records, arrays and sets (up to 256 bytes), also as F(a).x or F[i]. absolute places a variable over another one or at an address; outside bank 0 (for example absolute $310000) it is for simple variables and records.

Standalone programs: F7 saves the program as a .MER that runs without the cartridge: start it with Load program in the MiSTer menu, from ATLAS or over the network, like a program from the PC compiler, with Ctrl+R in the PASCAL editor, or from BASIC with BRUN "NAME" (drive optional: BRUN "NAME",3; needs a MERIDIAN core from 22 November 2026 on). BRUN keeps BASIC's memory while the program runs, so BASIC carries on afterwards, also with the next statement of a BASIC program. The file carries the program, the parts of the library it needs at run time (about 33 KB) and a small loader; it loads at $22:0000, so it needs the SDRAM module. When no cartridge is inserted the loader puts the library at $40:0000, where the cartridge would be. With the PASCAL cartridge it was made with, it uses the cartridge's copy. If a different cartridge is inserted, or a PASCAL cartridge with a different library, it prints a message and returns. Rebuilding the cartridge after changes to the editor or the on-device compiler keeps the library's fingerprint; after changes to the library units, the runtime or the 65C816 code generator, save the program again with F7.

SCHUB programs: press Ctrl+T, or put {$SCHUB} or (*$SCHUB*) at the very top of the text (the PC compiler ignores it), and the MERIDIAN compiles the program to RV32IM code for the SCHUB co-processor instead of 65C816 code. The language is the same, the whole library is there (the cartridge carries an RV32 build of every unit), and F5 runs the program on SCHUB: the 65C816 hands it over to SCHUB and serves its screen, keyboard and disk requests. F7 saves it as a standalone .MER that runs without the cartridge, too. On SCHUB, pointers are 32 bits, record fields are aligned like the PC compiler lays them out, FOR and CASE take longints, and variables are no longer limited to bank 0: the program's variables (up to 320 KB, 64 KB per variable) start at $0A:0000, followed by the heap, which runs up to the stack below $20:0000. Code goes to $08:0000 (up to 128 KB), the RV32 library to $04:0400. SCHUB needs the SDRAM module; the host stub switches SCHUB on if it is off in the menu.

C: C has a cartridge of its own, C.MOD, with the same editor and a disk, C.DSK (C in the cartridge).

The assembler on the cartridge

The PASCAL cartridge also assembles. A text whose name ends in .ASM (or .S), or whose first character is ;, is assembly: F9 assembles it, F5 runs it, F7 saves it as a .MER (in BASIC BRUN "NAME"), and the status line shows ASM 65C816 or ASM SCHUB. Errors put the cursor on their line. The syntax is the one of the PC assemblers the compiler uses (compiler/asm816.js, compiler/asmrv.js): the same source gives the same bytes. Examples: examples/hello.asm and examples/hellorv.asm. Both greet, then show the mouse position on one line until a click or Esc.

; HELLO.ASM
CHROUT  = $FFC1         ; kernel: print the character in A
        * = $2000
start   sep #$20        ; A 8 bit
        rep #$10        ; X, Y 16 bit
        .as
        .xl
        ldx #0
-       lda msg,x
        beq +
        jsl CHROUT
        inx
        bra -
+       rtl
msg     .text "HELLO!", 13, 0

65C816. Labels start in the first column (a colon after them is allowed); instructions are indented. * = address sets the origin (without one, $2000); name = expression defines a constant. Directives: .byte .word .long (24 bit) .dword .text "..." .fill n[,value] .align n, and .al .as .xl .xs for the width of immediates (16 bit until told otherwise). The operand size follows the value (direct page, absolute, long) or @b @w @l before the operand; a symbol defined further down is always absolute (use @l for one in another bank). Anonymous labels: a line starting with - or +, reached with bne -, bra +, --, ++. Expressions: $hex %binary decimal, 'c', * (the address of the line), + - * / << >> & |, parentheses, and <x low byte, >x high byte, ^x bank. Branches out of range are errors (use brl or jmp). Names are not case sensitive, up to 15 characters.

A program is called with JSL and returns with RTL, like any MERIDIAN program (F5, BRUN, Load program). It starts in native mode with D = 0; set the register widths it needs. It starts at the label START if there is one, else at its first byte. F5 runs programs placed at $2000–$B7FF (bank 0 is saved meanwhile) or in banks $04–$1F, within one bank.

SCHUB. With .schub as the first line (comments before it are fine), or Ctrl+T, the text is RV32IM assembly: registers x0–x31 and zero ra sp gp tp t0–t6 s0–s11 a0–a7 fp, labels with a colon, comments with ; or #, .byte .half .word (32 bit) .fill .align .text, and the pseudo-instructions li la mv not neg seqz snez j jr ret call tail nop beqz bnez bltz bgez bgtz blez bgt ble bgtu bleu. The code starts at $04:0400, behind the cartridge's 65C816 host stub (the .MER carries it), and sets its own stack (li sp, $7FFF0). It talks to the 65C816 through the mailbox at $800403F0: a1 to +8, the request in a0 to +4, then 1 to +0; when +0 reads 2, the answer is at +12, and +0 is set back to 0. Requests: 1 print the character a1, 2 read a key (0 = none), 3 Esc pressed?, 4 end the program. Chip registers are read and written directly through the uncached alias, e.g. the mouse at $8000C120.

The mouse (both CPUs): PFORTE holds X at $C120 and Y at $C122 (16 bit each) and the buttons at $C124 (bit 0 left, 1 right, 2 middle). They are a copy taken at the last write to $C12A, so write that register (any value) before each look.

The assembler keeps its tables in expansion RAM (output $33:0000, up to 256 KB; symbols $38:0000, up to 2000). A line can be up to 250 characters; an expression up to 100. On a MiSTer it assembles about 40 to 80 lines a second.

Identifiers are significant to 15 characters.

Memory used by the cartridge: source text $20:0000, loading area $28:0000, compiled code $30:0000, saved bank 0 $31:0000, program data image $32:0000. Compiled programs get bank 0 from about $2670 (variables and heap), stack from $A7FF and string temporaries from $B7FF.

Language

MERIDIAN Pascal follows Turbo Pascal 7 for the core language: programs and units, nested procedures and functions, value, var and const parameters, records (with variant parts), arrays, sets, pointers, enumerations, subranges, short strings, typed constants and a software real. Identifiers are not case sensitive.

From Turbo Pascal 5.5 and 7 there are also goto and label (within a routine, also out of loops), open array parameters (procedure Sum(const a: array of integer) with Low, High and SizeOf), procedural types (type TFunc = function(x: integer): integer;; a value is a global routine of the program or a unit, called as f(3), compared with nil and tested with Assigned; @Routine gives its address), and objects:

type
  PShape = ^TShape;
  TShape = object
    x, y: integer;
    constructor Init(ax, ay: integer);
    destructor Done; virtual;
    function Area: integer; virtual;
  end;
  TRect = object(TShape)
    w, h: integer;
    constructor Init(ax, ay, aw, ah: integer);
    function Area: integer; virtual;
  end;

constructor TRect.Init(ax, ay, aw, ah: integer);
begin
  inherited Init(ax, ay);      { or TShape.Init(ax, ay) }
  w := aw; h := ah;
end;
...
var p: PShape;
begin
  p := New(PRect, Init(1, 2, 3, 4));
  WriteLn(p^.Area);             { 12: through the VMT }
  Dispose(p, Done);
end.

Objects have fields, methods, inheritance, virtual methods (a constructor links the object to its type's table of virtual methods), constructors and destructors, Self, inherited, New(p, Init(...)), New(PType, Init(...)) and Dispose(p, Done); a descendant can be passed for a var parameter of its ancestor's type and assigned to an ancestor variable (the ancestor's part is copied). private and public are accepted and have no effect.

Statements

begin..end, if..then..else, case (with ranges and else), while, repeat..until, for..to/downto, with, Break, Continue, Exit, Halt, and the compound assignments += and -=. Boolean and/or short-circuit.

Expressions

Operators in Pascal precedence: not @ -; * / div mod and shl shr; + - or xor; = <> < <= > >= in. Integer arithmetic is done in 16 bits when both operands fit, otherwise in 32 bits (as in Turbo Pascal, integer with word becomes longint). / always gives a real. shr is a logical shift; use div to divide signed numbers. Numbers: 123, $7F, %1010, 1.5e3; characters 'a', #13, #$0D.

Memory and hardware access

Mem[a], MemW[a] and MemL[a] read and write bytes, words and longs at any 24-bit address: chip RAM, expansion RAM, chip registers. They work the same on both targets (on SCHUB through the uncached alias, as the chips need).

Mem[$C000] := 4;            { PINSEL layer A: bitmap with 256 colours }
MemW[$C120] := 160;         { PFORTE: mouse x }
x := MemL[$03F000];         { chip RAM bank 3 }

absolute places a variable at an address. On the 65C816 such variables must be in bank 0; ordinary pointers also address bank 0 there (the program, its variables, heap and stack all live in bank 0).

On SCHUB, keep the 32-bit alignment rule in mind: MemL and MemW on odd addresses cause an exception. Write such registers byte by byte.

Conditional compilation

{$IFDEF x}, {$IFNDEF x}, {$ELSE}, {$ENDIF}, {$DEFINE x}, {$UNDEF x} and {$I file}. Predefined: MERIDIAN, and M816 + CPU65C816 or SCHUB + CPURV32. At run time, Target returns TargetM816 or TargetSchub.

Range and overflow checks

As in Turbo Pascal, {$R+} turns range checks on and {$R-} off again, {$Q+} and {$Q-} the same for overflow checks (also together: {$R+,Q+}). Both are off at the start, and they count from where they stand in the text, on the PC and on the MERIDIAN, for both CPUs.

  • {$R+}: array and string indexes must be within their bounds, and a value assigned to an ordinal variable must fit its type (byte, 0..9, an enumeration ...); else the program stops with RUNTIME ERROR 201.
  • {$Q+}: the result of + - * on integers, and of Inc/Dec, must fit its type; else RUNTIME ERROR 215. Arithmetic on words (with constants that are not negative) is checked against 0..65535, on integers against -32768..32767, on longints against 32 bits.

The checks cost code and time; turn them on while a program is being written, and off around the parts that must be fast.

Files

As in Turbo Pascal: Text, file of T and file, with Assign Reset Rewrite Append Close Erase Rename Eof Eoln Seek FilePos FileSize Truncate Flush BlockRead BlockWrite IOResult, and Read/ReadLn/Write/WriteLn with a file first (records with Read(f, r)/Write(f, r)).

var t: Text;
    s: string;
begin
  Assign(t, 'NOTES.TXT');           { or '3:NOTES.TXT' for drive 3 }
  Rewrite(t);
  WriteLn(t, 'SCORE ', 1200);
  Close(t);
  Reset(t);
  ReadLn(t, s);
  Close(t);
end.

Files are on the current drive: the one the program was loaded from (SetDrive in the Dos unit changes it), or the drive in front of the name (0:–3:). The MERIDIAN's DOS reads and writes whole files, so a file is kept in a buffer while it is open: Reset loads it, Close saves what was written (a file not closed is not saved). The buffers are banks $E1–$E7 of expansion RAM: a file can be up to 64 KB, and up to 7 can be open. Text files are written with CR LF at the ends of lines; reading takes CR LF, LF or CR.

I/O errors stop the program ({$I+}, the default): RUNTIME ERROR 2 file not found, 4 too many open files, 100/101 read/write error, 102 not assigned, 103 not open, 104/105 not open for reading/writing, 106 a bad number in a text file, 150 write protected, 152 no disk. With {$I-} the program goes on and IOResult gives the error (and sets it back to 0).

Units

unit Tools;
interface
function Twice(x: integer): integer;
implementation
function Twice(x: integer): integer;
begin Twice := 2 * x; end;
begin                          { optional initialisation }
end.

A unit is found as name.pas next to the program or in lib/. System is used automatically. Routines that a program never calls are left out of the output, so using a big unit costs only what you use.

Differences from Turbo Pascal

  • No asm blocks, no Delphi classes, no dynamic arrays, no dynamic methods (virtual n is read as virtual).
  • A procedural value is a global routine, not a nested one; procedural types have no open array parameters. The cross compiler's far code model (units in the cartridge) has no procedural calls.
  • real is IEEE single precision (Turbo Pascal's is 6 bytes).
  • Range and overflow checks only with {$R+} and {$Q+} (above); division by zero always stops the program with runtime error 200.
  • Read/ReadLn read from the keyboard only, with a small line editor (Backspace, Return; Esc ends the program).

C

The same toolchain compiles C. In the IDE, open a .c file (or New → C program) and press F5: it is built by the C front end and the same back ends as Pascal, for the 65C816 or SCHUB (the Target menu), and runs in the emulator; F8 sends it to the MiSTer. On the command line:

node compiler/mcc.js examples/mandel.c               # -> examples/mandel.mer (65C816)
node compiler/mcc.js examples/mandel.c -t schub -S   # SCHUB, and the assembly

The language

C89 with the common C99 parts: // comments, declarations anywhere and in for (int i = 0; ...), _Bool and <stdbool.h>, designated initializers ({ .x = 1, [3] = 5 }), compound literals ((int[]){ 1, 2 }), inline (accepted, not used), variadic macros, __func__, _Static_assert, typeof, and GNU case ranges (case 1 ... 5:). Structs, unions, bit-fields, enums, typedef, function pointers, structs as arguments and results, static locals, goto, switch. The preprocessor has #include, #define (object and function-like, #, ##, __VA_ARGS__), #undef, #if/#ifdef/#ifndef/#elif/#else/#endif with defined, #error, #warning, #pragma once, __FILE__ and __LINE__. Predefined: __MERIDIAN__, __M816__ and __65C816__, or __SCHUB__ and __riscv; __STDC_VERSION__ is 199901L.

A program can be several files. A header can say #pragma link "util.c": the file (next to the one that says it, or in clib/src) is compiled into the program once. mcc also takes several files. Functions and variables that are not static are shared by name; a name used but defined nowhere is an error (undefined reference).

On SCHUB, struct members are aligned to their size (as the hardware needs); on the 65C816 they are packed. size_t is unsigned int on the 65C816 and unsigned long on SCHUB.

A pointer declared __far (unsigned char __far *p) holds a 24-bit address and reaches all of memory: chip RAM, expansion RAM, the chips' registers. On SCHUB it goes through the uncached alias, as access to the chips must. A near pointer converts to a __far one (FARPTR(p)); pointer arithmetic and indexing work as usual. <meridian.h> has PEEK(a), POKE(a, v) and the 16 and 32-bit PEEKW POKEW PEEKL POKEL, all lvalues on __far pointers:

#include <meridian.h>
unsigned char __far *vram = (unsigned char __far *)0x020000L;   /* the Graph bitmap */
vram[320 * y + x] = colour;
POKE(0xC00B, 1);                                                /* frame interrupt on */

The C library

In clib/, compiled with the program (only what is used ends up in it):

  • <stdio.h>: printf, sprintf, snprintf, fprintf and the v forms with %d %i %u %x %X %o %b %c %s %p %f %e %g %n %%, flags - + space 0 #, width, precision, * and l h z; scanf, sscanf, fscanf (%d %u %x %o %f %s %c %[...] %n); putchar puts getchar gets fgets fputs fgetc fputc ungetc; fopen fclose fread fwrite fseek ftell rewind feof ferror fflush remove rename perror. stdout is the screen (through the kernel, like Write), stdin the keyboard a line at a time (like ReadLn). Files are those of the System unit (up to 64 KB, on the drive given by a name like "1:DATA.TXT", the current drive otherwise); bytes are read and written as they are ('\n' is 10).
  • <stdlib.h>: malloc calloc realloc free (the System heap; NULL when it is full), exit atexit abort, atoi atol atof strtol strtoul strtod, abs labs div ldiv, rand srand (RAND_MAX 32767), qsort bsearch, itoa ltoa.
  • <string.h>, <ctype.h>, <math.h> (sin cos tan asin acos atan atan2 sinh cosh tanh exp log log10 log2 pow sqrt cbrt hypot floor ceil trunc round fabs fmod modf frexp ldexp fmin fmax isnan isinf, and the f names), <time.h> (clock() counts frames, CLOCKS_PER_SEC is 60; time() reads the real-time clock; mktime gmtime localtime asctime ctime strftime), <stdarg.h>, <stdint.h>, <stddef.h>, <limits.h>, <float.h>, <assert.h>, <errno.h>, <stdbool.h>.

main may be int main(void) or int main(int argc, char **argv) (argc is 1). Its result becomes ExitCode. As in Pascal, Esc while the program reads the keyboard (getchar, scanf, ReadKey with CheckBreak) ends it; a long loop can test EscPressed().

Library units from C

<crt.h>, <graph.h>, <sprites.h>, <input.h>, <audio.h>, <dos.h>, <blitter.h>, <copper.h>, <schub.h>, <basic.h> and <workshop.h> make a unit's routines, constants, variables and types visible under their Pascal names, in any case: ClrScr() or clrscr(), TextColor(Yellow), if (KeyDown(scEsc)). Each header quotes the unit's interface. The System unit is always visible (EscPressed(), Random(10), KernelMode(80), IntToStr(n), MemAvail(), ...). A routine without parameters is called with (). Your own units work the same way: #pragma unit myunit makes myunit.pas next to the program visible.

asm blocks in C

asm { ... } is a statement of assembly for the target, exactly as in Pascal (one instruction a line, ; comments, labels as name:), with C names: the function's locals and parameters stand for their places in the frame, globals for their addresses, enum constants for their values. On the 65C816, D is the frame (lda n); on SCHUB a local is an offset from s0 (lh t1, n(s0)) and every parameter takes 4 bytes. Use #ifdef __SCHUB__ to write both (see tests/ccases/15_asm.c). asm("...") with a string works too.

Things to know

  • Arguments are evaluated from the last to the first (C leaves the order open): printf("%d %d", f(), f()) calls the second f first.
  • No 64-bit integers, no setjmp/longjmp, no variable-length arrays, no K&R parameter lists, no wide characters. const and volatile are accepted (every access goes to memory anyway).
  • Calling a function that was not declared declares it as int f(), with a warning.
  • The C cartridge compiles C on the MERIDIAN itself, with a few things fewer (C in the cartridge).

C in the cartridge

C has a cartridge of its own, C.MOD, and a disk to go with it, C.DSK:

node compiler/mkcart.js --c      # C.MOD   (npm run ccart)
node compiler/mkcdisk.js         # C.DSK   (npm run cdisk)

Copy both to /media/fat/games/MERIDIAN/; insert C.MOD as the cartridge and C.DSK under Drive 1 or Drive 2. The disk is an 8 MB FAT16 image like the core's: the headers of clib/include, the C library's sources (clib/src, to read: the library itself is in the cartridge) and the C examples (F6 picks the drive, F3 opens one). #include looks on the current drive, then on drives 1, 2 and 3; without the disk the compiler says a header is missing. The cartridge starts into the PASCAL cartridge's editor, built for C (on a core with SCHUB its SCHUB build): every text that is not assembly is C, and a new text is a C program. F9 compiles it, F5 runs it (with the debugger's breakpoints and stepping, and runtime errors on their line), F7 saves a standalone .MER, and the status line shows C 65C816 or C SCHUB. Ctrl+T, or #pragma schub as the first line, makes SCHUB code. The editor colours C's comments, strings, # lines and keywords. It works the same in the SCHUB build of the editor, and gives the same bytes there.

The compiler (cart/ccomp.inc with cpre.inc, ctype.inc, cexpr.inc, cstmt.inc) is part of the on-device compiler cart/ncomp.pas built for the C cartridge (CCART): it writes 65C816 or RV32IM code directly, with the PC compiler's data model and calling convention (arguments from the last to the first on the stack, the caller removes them, a struct result through a hidden first pointer). The C library is clib/ compiled by the PC compiler into the cartridge's library block, built for the far code model (function pointers are 32 bits there: code addresses are 24 bits). The library units work through #pragma unit, as on the PC. A function's body is read twice, once to learn the size of its frame; so declarations may stand anywhere.

Not in the cartridge: bit-fields, compound literals, asm blocks, your own Pascal units, programs of several .c files, old-style declarations. The address of a function can be taken only after its definition (library functions any time); a block can declare a function only if the file declares it too; string literals have at most 255 characters. tests/nccrun.js compiles the tests/ccases that need none of these on the MERIDIAN, for both CPUs, and compares their output with the PC compiler's.

Targets

65C816 (MERIDIAN 816)

The program is native 65C816 code in bank 0, loaded at $2000 and started by the kernel with JSL (from the MiSTer menu, tools/senden.py, or the monitor's G 2000). It returns with RTL; the kernel then restarts BASIC with READY..

AddressUse
$00:2000code, constants, initialised data
after itvariables (cleared at start), then the heap growing upwards
$00:B7FFtop of the stack, growing down (BASIC's extension at $B800 is left alone)
$02:0000Graph unit picture (76 800 bytes)
$03:8000Copper unit list (default)

Machine model while Pascal code runs: native mode, A and X/Y 16 bit, data bank 0, D = frame pointer of the current procedure (locals are direct-page variables). Kernel routines are called with D = 0 and an 8-bit accumulator, as the kernel expects; its interrupt handler saves D and the data bank itself, so the frame pointer is safe.

Calling convention: arguments are pushed left to right (2 bytes for 16-bit values and pointers, 4 for 32-bit values); nested procedures get the frame of the enclosing procedure as a hidden last argument (static link); JSR/RTS; results in A, 32-bit results in A (low) and X (high); the caller removes the arguments.

SCHUB (RV32IM co-processor)

Needs the MERIDIAN 816 + SCHUB core with an SDRAM module. The .MER file loads at $04:0000 and holds two programs:

AddressUse
$04:000065C816 host stub, started by the kernel with JSL
$04:03F0mailbox (SCHUB uses the uncached alias $8004_03F0)
$04:0400RV32IM code and data, then variables and heap
$07:FFF0top of the SCHUB stack

The stub checks that SCHUB is there ($CD00 = SCHB), sets the start address, switches SCHUB on ($CD08 = 3) and then serves the RISC-V program: it prints characters, reads keys, switches the text mode, resets the display and calls the DOS for it, through the kernel's long entry points. Everything else — graphics, sprites, sound, blitter, copper, timers — the RISC-V program drives directly through the chip registers. Esc stops a SCHUB program even while it computes. If SCHUB is missing the stub prints SCHUB NOT AVAILABLE.

Code generation: the expression stack lives in the callee-saved registers s1–s11, s0 is the frame pointer, arguments are pushed in 4-byte slots, results come back in a0. 16-bit values are kept sign- or zero-extended in the 32-bit registers. Variables are cached; Mem[] and absolute variables use the uncached alias.

DOS calls on SCHUB: the 65C816 moves the file data, so read data that the DOS loaded into a Pascal variable may still be stale in SCHUB's data cache. Load into a free memory area and read it with Mem[], which is uncached.

Basic — the variables of the BASIC program that started this one

A program started from MERIDIAN BASIC with BRUN "NAME" can read and set that BASIC program's variables. Names are written as in BASIC: 'SC' a number, 'N%' an integer, 'A$' a string. Only the first two characters count, like in BASIC ('SCORE' is SC). A variable BASIC has not used yet reads as 0 or ''; the Set routines create it. BASIC sees the new values as soon as the program ends.

10 W=320:H=200:T$="MANDEL"
20 BRUN "CALC",3
30 PRINT T$;" TOOK";MS;"MS, RESULT";R%
program Calc;
uses Basic;
var w, h: real;
begin
  w := BasicReal('W'); h := BasicReal('H');
  { ... }
  SetBasicInt('R%', 42);
  SetBasicReal('MS', 1234.5);
  SetBasicStr('T$', BasicStr('T$') + ' (PASCAL)');
end.

Numbers are converted between BASIC's 5-byte format (about 9 digits) and real (about 7). The unit works on both targets and in programs made with the cartridge. How it works: BASIC keeps its program and variables in bank 1, which BRUN leaves alone. BRUN keeps BASIC's page zero, with the pointers to the variables ($87–$94), in bank $E0 while the program runs and puts it back afterwards. The unit reads and changes the pointers there.

How it works

  1. compiler/lexer.js, front.js: a one-pass Turbo Pascal-style front end. Declarations go into the symbol table, expressions become typed trees, statements become a small stack-machine IR.
  2. compiler/back816.js turns the IR into 65C816 assembly (the top of the expression stack cached in A/X, constants kept pending), asm816.js assembles it (64tass-compatible, with branch relaxation).
  3. compiler/backrv.js turns the same IR into RV32IM assembly with the expression stack in s1–s11, and builds the 65C816 host stub; asmrv.js assembles it.
  4. Unused routines are removed, the bytes get a 16-byte MER header.
  5. emu/ has a complete 65C816 core, an RV32IM core, and the MERIDIAN chips (PINSEL text/tiles/bitmaps, KOBOLD sprites, LOTSE copper, KRAN blitter, PFORTE input and clock, ORGEL voices through WebAudio, SCHUB registers, DOS on a virtual drive). It runs the real kernel ROM.
